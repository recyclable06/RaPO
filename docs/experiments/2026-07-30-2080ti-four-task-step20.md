# RTX 2080 Ti 20-step four-task comparison (2026-07-30)

## Scope and status

Status: **passed** for a four-task GRPO/RaPO engineering gate on 8 x RTX
2080 Ti. Both method chains completed task-4 training, save, reload, and the
same fixed evaluation. The resulting bounded comparison favors GRPO, but it is
not a paper-level result because it uses one class order, one run, 20 optimizer
steps per task, and a 20-image-per-class evaluation subset.

Task-4 training used RaPO repository commit `c4d9b18`, the pinned Visual-RFT
commit `2ffad63b25ddd79bfe25d3e046645401201c89d6`, and the configuration from
the three-task gate: FP16, SDPA, ZeRO-3 CPU optimizer offload, gradient
accumulation 2, gradient checkpointing, 512 prompt tokens, 32 completion
tokens, 100,352 image pixels, and eight generations. Each method started from
its own task-3 final model.

## Result audit

The two task-4 prediction files contain the same 1,600 ordered
`(after_task, eval_task, relative_path, target)` keys, 400 per task, with no
duplicates or missing parsed answers. On task 1, 281 examples are correct for
both methods, 64 are correct only for GRPO, none are correct only for RaPO, and
55 are wrong for both.

The RaPO errors are concentrated in several semantically neighboring classes,
including `german shepherd dog` becoming `collie` or `whippet`, `orangutan`
becoming `chimpanzee`, and `toy poodle` becoming `poodle`. This pattern is
consistent with interference from newly introduced labels, but it does not by
itself establish the cause. The ZeRO-3 integration constructs the frozen
reference model from the current run's input model ID, and the serialized RaPO
state is continuous through task 4; no evaluation misalignment, duplicate
sample, missing answer, checkpoint-save failure, or anchor-path defect was
found.

## Decision

The four-task engineering gate passes, while the bounded accuracy comparison
now materially favors GRPO. This is evidence that the present short-budget
configuration does not yet reproduce RaPO's reported advantage, not evidence
against the paper. Continue the paired chain through task 5 with unchanged
settings so the predeclared order remains intact; treat a repeated or growing
gap as a trigger for a focused implementation-versus-paper audit before a
larger multi-order experiment.
