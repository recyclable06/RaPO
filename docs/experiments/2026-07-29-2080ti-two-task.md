# RTX 2080 Ti reduced two-task comparison (2026-07-29)

## Scope and status

Status: **passed** for a reduced two-task GRPO/RaPO comparison on the available
8 x RTX 2080 Ti node.

This result validates sequential checkpoint loading, RaPO state transfer,
Retention Reward, CTAN, bounded inference, and continual-metric calculation.
It is not a paper result: each task used only five optimizer steps, generation
budgets were reduced, and evaluation used five fixed test images per class.

## Provenance and configuration

- RaPO training repository commit: `c0d299b`
- bounded evaluation runner commit: `3f67d15`
- Visual-RFT upstream commit: `2ffad63b25ddd79bfe25d3e046645401201c89d6`
- model: Qwen2-VL-2B-Instruct, 2,208,985,600 parameters
- data: ImageNet-R order 0, Visual-RFT exports for tasks 1 and 2
- hardware: 8 x NVIDIA GeForce RTX 2080 Ti

Both methods used FP16, PyTorch SDPA, ZeRO-3 with CPU optimizer offload,
gradient accumulation 2, gradient checkpointing, 512 prompt tokens, 32
completion tokens, 100,352 image pixels, eight generations, and an initial
loss scale of 2,048. Each task ran for five optimizer steps from the preceding
task's final model.

## Bounded evaluation

For every stage and observed class, evaluation selected the first five test
images after sorting by the manifest's relative path. This yields 100 samples
for stage 1 and 200 for stage 2. Generation was greedy with at most 32 new
tokens, and correctness used the repository's strict normalized
`<answer>...</answer>` matcher.

| Method | Accuracy after task 1 on task 1 | Accuracy after task 2 on task 1 | Accuracy after task 2 on task 2 | Last Accuracy | Forgetting |
| --- | ---: | ---: | ---: | ---: | ---: |
| GRPO | 90/100 | 90/100 | 95/100 | 92.5% | 0.0% |
| RaPO | 90/100 | 89/100 | 95/100 | 92.0% | 1.0% |

The methods differ by one prediction in this bounded sample. The result is too
small to rank them and should not be interpreted as evidence against or for
RaPO. It only establishes a deterministic end-to-end comparison path.

## Integration issue found

The first task-2 attempt failed before training because Visual-RFT selected its
model class by searching for `Qwen2-VL` in the checkpoint path. A sequential
output directory need not contain that substring. Commit `c0d299b` changes
policy, reference-model, and processor dispatch to use the checkpoint's
`AutoConfig.model_type`. The patched checkout then loaded the task-1 output and
completed both task-2 methods.
