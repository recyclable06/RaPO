# RTX 2080 Ti reduced smoke test (2026-07-29)

## Scope and status

Status: **passed** for the reduced GRPO training path on the available
8 x RTX 2080 Ti node.

This is a hardware-compatibility and training-plumbing result. It is not a
paper reproduction result: RaPO was disabled, the rollout count was reduced to
two, and the prompt, completion, and image budgets were reduced.

## Provenance

- RaPO repository commit for the successful one-step run: `f005605`
- RaPO repository commit for the five-step run: `d822934`
- Visual-RFT upstream commit: `2ffad63b25ddd79bfe25d3e046645401201c89d6`
- Model: Qwen2-VL-2B-Instruct, 2,208,985,600 parameters
- Dataset: ImageNet-R order 0, Visual-RFT task 1 export
- Training environment: `rapo-train`, PyTorch 2.5.1, DeepSpeed 0.15.4
- Hardware: 8 x NVIDIA GeForce RTX 2080 Ti, compute capability 7.5

The reduced configuration used FP16, PyTorch SDPA, ZeRO-3, CPU optimizer
offload, gradient accumulation 2, gradient checkpointing, two generations,
512 prompt tokens, 32 completion tokens, and an image budget of 100,352 pixels.
Dynamic FP16 loss scaling started at 4,096.

## Results

### Model-load gates

The frozen base model loaded on one RTX 2080 Ti in 11.12 seconds. Peak PyTorch
memory was 4,215 MiB allocated and 4,528 MiB reserved.

The final model from the five-step run also loaded successfully on one RTX 2080
Ti. It reported the same parameter count, 45.71 seconds load time, 4,215 MiB
peak allocated memory, and 4,528 MiB peak reserved memory.

### FP16 loss-scale diagnosis

Three initial one-step trials started dynamic loss scaling at 65,536. All
completed without OOM, but reported a zero gradient norm despite nonzero
grouped reward variance. Inspection of the saved DeepSpeed optimizer state
showed `overflow=True` and an empty Adam state, proving that the optimizer step
had been skipped. Disabling gradient checkpointing did not change this result.

Reducing `initial_scale_power` from 16 to 12 fixed the skipped update. The
successful one-step run reported:

- `grad_norm=8.20528507232666`
- `reward_std=0.2651650309562683`
- DeepSpeed optimizer `overflow=False`
- Adam `step=1`, with nonempty `exp_avg` and `exp_avg_sq` tensors
- no OOM and no residual GPU process

An `nvidia-smi` snapshot near the high-memory phase showed 10,102--10,398 MiB
used per GPU. This is an observed snapshot, not an instrumented peak.

### Five-step stability gate

The five-step run used all eight GPUs and `RAPO_SMOKE_SAVE_STRATEGY=no`.
This avoided writing the roughly 26 GiB distributed optimizer state while
retaining the final model.

| Step | Loss | Gradient norm | Reward | Reward std | KL |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.0000 | 8.2082 | 0.25000 | 0.26517 | 0.00000 |
| 2 | 0.0048 | 10.1267 | 0.34375 | 0.13258 | 0.11887 |
| 3 | 0.0048 | 16.5121 | 0.46875 | 0.22097 | 0.12073 |
| 4 | 0.0082 | 14.3893 | 0.81250 | 0.17678 | 0.20459 |
| 5 | 0.0069 | 12.0072 | 0.75000 | 0.17678 | 0.17255 |

Training took 141.17 seconds, or 0.035 optimizer steps per second. Every
gradient norm was finite and nonzero; no FP16 overflow, NaN, or OOM was
observed. DeepSpeed reported allocator cache flushes after later steps, so this
configuration is stable for the bounded gate but has limited memory headroom.

## Decision

The available node is sufficient for reduced GRPO/RaPO integration work, so a
newer GPU is not yet required. The next hardware gate is one step with the
paper rollout count of eight while retaining the reduced token and image
budgets. A newer card should be requested if that gate OOMs or if increasing
the paper-locked sequence/image budgets exceeds the 2080 Ti memory ceiling.
